# Liktu Community

**让结构图成为人和 AI 都能读懂、复用和继续完善的知识。**

Liktu 是一个在线绘制 ER 图与流程图，并将结构导出为 AI 可读 Markdown 的工具。它希望把「画出结构」和「说明结构」连在一起：图不仅便于人理解，也能成为清晰、可携带、可继续加工的文档。

`liktu-community` 是 Liktu 的公开内容仓库，负责提供可复用的模板、案例和配套说明。它与 Liktu 前端分工协作：前端负责编辑和导出，community 负责沉淀、组织与分享内容。

## 初衷与愿景

很多有价值的知识藏在白板、截图或个人文件里，难以复用，也很难交给 AI 继续理解。Liktu 希望让结构表达更轻量：打开网页即可绘制，不必先搭建复杂环境；导出的 Markdown 保留结构和上下文，方便分享、归档，也方便 AI 阅读。

Community 希望把零散的好图变成大家都能起步的素材。一个模板可以展示领域模型如何拆分，一份案例可以说明流程为何这样设计；其他人可以从它开始，按自己的业务修改，再把改进分享回来。长期来看，这里会成为开放、可检索、可演进的结构知识库，而不只是模板下载页。

我们重视：

- **开放与易用**：内容公开，以简单文件格式保存，尽量降低使用和贡献门槛。
- **可理解**：模板有清晰名称、说明和实际内容，帮助使用者知道它表达什么、适用于哪里。
- **可复用**：从真实问题中提炼可修改的起点，而不是只有图片供参考。
- **人和 AI 都能读**：结构源文件便于工具解析，说明文档补足必要背景。
- **循序演进**：先把模板和案例做好，再根据真实需要扩展社区能力。

## 网站与仓库如何协作

```text
使用者
  │
  ▼
Liktu 前端（绘制、编辑、解析、导出 Markdown）
  │ 读取静态目录和模板文件
  ▼
liktu-community（模板、案例、说明和目录索引）
```

Liktu 前端提供 ER 图、流程图和文档工作台。Community 通过静态文件提供内容：前端读取 `templates/index.json`，再下载对应源文件。

- ER 图读取 `format: dbml` 的 DBML。
- 在线流程图读取 `format: drawio` 的 `.drawio`。首页案例用流程模板 id 打开时，会把同名 `.mmd` 换成 `.drawio` 再载入。
- 文档工作台和 `/flow/` 继续使用 Mermaid 源文件。

内容仓库不负责账号、云端保存、协作或动态 API；这些能力只有在出现明确需求后才另行评估。

模板目录由 `schemaVersion` 标记格式版本。每个条目包含唯一 `id`、名称、类型、格式、简介、源文件路径、版本和更新时间。文件路径相对于仓库根目录，便于 GitHub Pages 等静态托管直接提供。

## Community 可以提供什么

当前仓库以可编辑源文件和案例说明为主：

- **ER 模板**：以 DBML 描述实体、字段、枚举和关系。
- **流程图模板**：同一流程通常同时提供 Mermaid（`.mmd`）和 diagrams.net（`.drawio`）。在线流程图打开 `.drawio`；Mermaid 文件供文档预览和 Mermaid 编辑器使用。
- **案例与说明**：解释模板表达的场景、关键关系和适用范围。

仓库提供资料审核流程、机器人智能调度和 JetLinks 物联网平台等学习案例，以及智慧空间协同运营、服务行业 AI Agent、企业信用与融资服务、企业数据治理与 BI 四个基于个人项目经验抽象的行业方案。行业方案配有案例说明、ER 模型和流程图。图示是概念模型，不对应任何特定企业的官方数据结构或完整实现规范。OptaPlanner 调度方案重点展示硬软约束、评分和 Late Acceptance 搜索；服务行业 Agent 方案重点展示编排、RAG、记忆和受控工具调用。机器人调度案例参考 Open-RMF 的多车队互操作理念，不是其官方数据模型。

> Community 提供静态模板与案例。Liktu 默认从已发布的 GitHub Pages 目录读取这些文件。

## 仓库结构

```text
.
├── templates/
│   ├── index.json               # 前端读取的模板目录
│   ├── er/                      # DBML 格式的 ER 模板
│   └── flow/                    # Mermaid 与同名 .drawio 流程图模板
├── examples/                    # 案例背景和阅读说明
├── LICENSE
└── README.md
```

GitHub Pages 从 `main` 分支根目录发布。模板目录与静态文件地址：

- Pages 站点：<https://liklicoming.github.io/liktu-community/>
- 模板目录：<https://liklicoming.github.io/liktu-community/templates/index.json>

上述地址需在仓库启用 Pages 后可用。若在本地查看，直接打开 `templates/index.json`，再按条目中的 `file` 路径找到源文件即可。

## 参与贡献

欢迎提交新模板、完善现有案例，或修正文档中的错误。每份内容请尽量做到：

1. ER 使用 DBML。流程图尽量同时提供可被 Liktu 打开的 Mermaid 和同名 `.drawio`。
2. 为模板设置稳定且唯一的 `id`，提供准确的名称、简短说明、版本和更新时间。
3. 在 `templates/index.json` 中登记模板；路径使用相对仓库根目录的正斜线路径，例如 `templates/er/example.dbml`。
4. 在 `examples/` 或模板附近补充背景、关键设计和适用范围，避免只有一段难以理解的源文件。
5. 内容应是你有权分享的原创或兼容许可内容，不提交隐私、凭据或真实业务敏感数据。

若使用者发现问题，也欢迎通过 Issue 描述场景、预期结果和相关模板路径。具体贡献流程会随仓库启用和社区规模逐步完善。
